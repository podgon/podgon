# Хостинг: план развёртывания и конфигурации

Решение владельца (2026-11-03): разворачиваемся поэтапно, от домашнего NAS к Selectel. Следующий шаг
делаем, только если текущего не хватает.

## План по шагам

| Шаг | Где | Зачем | Когда |
|---|---|---|---|
| Х1 | NAS дома, доступ только из домашней сети | Прототип, проверка приложения вживую на телефонах | Сейчас, до этапа 9 |
| Х2 | NAS дома + внешняя VPS с Caddy и WireGuard-туннелем до NAS | Публичный адрес для закрытого тестирования и публикации в стор | Перед публикацией (этап 9) |
| Х3 | Selectel: VM + управляемый PostgreSQL | Прод, если на Х2 будут сбои (свет, интернет, нагрузка, требования 152-ФЗ) | По факту проблем на Х2 |

Перенос между шагами — та же Compose-сборка (`deploy/`), плюс перенос БД (`pg_dump`/`pg_restore`) и смена
DNS-записи.

## Х1. NAS в домашней сети

Железо: youyeetoo NestDisk — Intel N150 (4 ядра, x86-64), 12 ГБ RAM, eMMC 64 ГБ под систему,
4 слота M.2 NVMe, 2 × 2,5 GbE, 11–25 Вт. Ресурсов с запасом больше, чем у рекомендованной VM (ниже).

- ОС: Linux с Docker (Ubuntu Server 24.04 LTS или OpenMediaVault); данные Docker и PostgreSQL — на NVMe, не на eMMC.
- Стек: `deploy/docker-compose.yml` (backend + PostgreSQL + Mailpit) — образ x86 тот же, что локально.
- У контейнера backend задать лимит памяти (`mem_limit`, например 2,5 ГБ): в Dockerfile
  `-XX:MaxRAMPercentage=75`, без лимита JVM считает от всей памяти машины.
- Клиент: сборка с `-Ppodgon.debugApiBaseUrl=http://<ip-nas>:8080` (адрес NAS в домашней сети закрепить в роутере).
- Почта: Mailpit на NAS (коды входа смотреть в его веб-интерфейсе) — достаточно для домашней проверки.
- Бэкап: периодический `pg_dump` на другой диск или ноутбук.

## Х2. NAS + внешняя VPS (Caddy + WireGuard)

Схема: `клиент → VPS (публичный IP, Caddy с TLS, limit_req) → WireGuard → NAS (backend)`.

- Белый IP дома не нужен, домашний адрес не публикуется, CGNAT и закрытые провайдером порты не мешают.
- VPS: самая простая (1 vCPU, 1 ГБ RAM, 10 ГБ SSD), в РФ (Selectel или другой российский провайдер).
  Зарубежные CDN и туннели (Cloudflare Tunnel и т. п.) не используем — ADR-010.
- На NAS backend слушает только интерфейс WireGuard; в `PODGON_TRUSTED_PROXIES` — адрес VPS в туннеле (R4).
- Mailpit заменяется настоящим почтовым провайдером, заглушка CAPTCHA — Яндекс SmartCaptcha (этап 9).
- NAS вынести в отдельный VLAN/DMZ, если роутер позволяет; ИБП для NAS и роутера желателен.
- Бэкапы БД — вне дома (объектное хранилище в РФ или VPS), с проверкой восстановления.

Риски Х2 (причины переезда на Х3): отключения света и интернета дома, DDoS или всплеск запросов
забивает домашний канал, договор провайдера может запрещать сервер на домашнем тарифе, меры защиты ПДн
по 152-ФЗ дома обосновать сложнее (уточнить у юриста на этапе 9).

## Х3. Selectel

Схема из `architecture.md` §7: облачная VM с Docker Compose за reverse proxy + управляемый PostgreSQL,
приватная сеть между ними, БД без публичного адреса, образы — в реестре контейнеров Selectel.

**VM (backend, Caddy, сборщик логов):**

| | Минимум | Рекомендуется |
|---|---|---|
| vCPU | 2 | 2, выделенные (не shared-core с долей 10–20 %: JVM упирается в лимит при старте и GC) |
| RAM | 2 ГБ | 4 ГБ (запас на обновление со сменой контейнеров) |
| Диск | 20 ГБ SSD | 30–40 ГБ SSD (образы, логи) |
| ОС | Ubuntu 24.04 LTS | — |

**Управляемый PostgreSQL:**

| | Старт | Когда расти |
|---|---|---|
| vCPU / RAM | 2 vCPU / 4 ГБ | 4 / 8 ГБ, если поиск (`ts_rank_cd` + триграммы) упрётся в CPU |
| Диск | 20–40 ГБ SSD | данных мало (текст и теги) |
| Версия | PostgreSQL 18 (если доступна, иначе 17) | — |
| Узлы | 1 | + реплика при реальной нагрузке |

Проверить при заказе: расширения `citext`, `pg_trgm`, `unaccent` (миграции V1, V7); возможность создать роль
`podgon_app` без DDL (R6; скрипты `deploy/db-init` выполнить вручную); бэкапы и PITR; состав и тариф защиты
от DDoS. Дополнительно: приватная сеть, публичный IP для VM, Selectel DNS, Container Registry.

Дешёвая альтернатива (против принятой архитектуры): одна VM 4 vCPU / 8 ГБ с PostgreSQL в Docker — бэкапы
(`pg_dump`/WAL-G в S3), обновления и мониторинг БД тогда свои. Тестовый стенд: VM 2 vCPU / 2–4 ГБ с БД в контейнере.

Размеры оценочные — подтвердить нагрузочным тестом (этап 10); в облаке меняются без переустановки.

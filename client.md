# Клиент (Android)

## Стек
| Область | Выбор |
|---|---|
| Язык | Kotlin (актуальная стабильная версия), Coroutines + Flow |
| UI | Jetpack Compose, Material 3, Navigation Compose (type-safe) |
| Архитектура | Clean Architecture-lite: UI → ViewModel (MVI/UDF) → UseCase → Repository → DataSource |
| DI | Hilt |
| Сеть | Retrofit + OkHttp + kotlinx.serialization (клиент генерируется из OpenAPI) |
| Локальные данные | Room (кэш), DataStore (настройки), EncryptedSharedPreferences/Keystore (токены) |
| Пагинация | Paging 3 (keyset по cursor) |
| Фоновые задачи | WorkManager (при необходимости) |
| Изображения | Coil (аватары — в будущем) |
| Тесты | JUnit 5/4, Turbine, MockK, Compose UI Test, MockWebServer |
| Качество | ktlint/Detekt, Android Lint, R8 |
| Сборка | Gradle (Kotlin DSL), version catalog, convention plugins |

minSdk — 26 (Android 8.0, покрывает >95%, на согласование), targetSdk — актуальный требуемый Google Play.

## Структура модулей

```
android/
├── app/                        точка входа, навигация верхнего уровня, DI-граф
├── core/
│   ├── common/                 утилиты, Result, диспетчеры
│   ├── model/                  доменные модели (чистый Kotlin, без Android)
│   ├── network/                Retrofit, интерцепторы (auth, refresh, error mapping)
│   ├── database/               Room
│   ├── datastore/              настройки, токены
│   ├── designsystem/           тема, компоненты
│   └── ui/                     общие Compose-компоненты
└── feature/
    ├── auth/                   регистрация, подтверждение, вход, восстановление
    ├── profile/                профиль, смена пароля, удаление аккаунта
    ├── groups/                 список групп, участники, роли, приглашения
    ├── categories/             дерево категорий и управление
    ├── reviews/                лента, карточка, создание/редактирование
    └── search/                 поиск и фильтры
```
В каждом feature-модуле: `ui/` (Screen, ViewModel, State, Event), `domain/` (UseCase, интерфейсы репозиториев), `data/` (репозитории, DTO-мапперы). `core/model` и `domain` — без зависимостей от Android для возможного переноса в KMP.

## Навигация и экраны

- Вне авторизации: Приветствие → Регистрация → Подтверждение email (ввод кода/переход по ссылке) → Вход → Восстановление пароля.
- После входа: нижняя навигация — **Лента** (все группы с переключателем группы), **Поиск**, **Группы**, **Профиль**.
- Лента: карточки рекомендаций (название, оценка, категория, теги, автор с ролью, группа), фильтры (категории деревом, теги, автор), pull-to-refresh, бесконечная прокрутка.
- Карточка рекомендации: полное описание, действия автора (редактировать/удалить/изменить группы).
- Создание/редактирование: название, описание, оценка (1–10), выбор групп → категория для каждой группы (с подстановкой по шаблону) → теги (ввод с `#`, автодополнение из тегов группы).
- Группы: список, создание, экран группы (участники с ролями, категории, приглашения, настройки), вступление по приглашению (deep link / ввод кода) с экраном выбора, чем поделиться (все / категории / подкатегории / теги / кроме… / ничего) и предпросмотром количества.
- Выход из группы: диалог с опцией «удалить мои отзывы в группе».
- Профиль: имя, displayName, bio, смена пароля, выход, удаление аккаунта (подтверждение паролем).
- Удаление категории: диалог с предупреждением и подтверждением; при наличии отзывов — дополнительное предупреждение, что отзывы будут удалены (данные берутся из `delete-impact`).
- Скрытие админ-действий для обычных участников (но сервер — источник правды по правам).

## Состояние и данные
- UDF/MVI: `UiState` (immutable), `UiEvent` (разовые эффекты), `Action`. `StateFlow` + `collectAsStateWithLifecycle`.
- Репозитории возвращают `Flow`; единый тип результата (`Success/Error`) с типизированными ошибками, маппингом `problem+json` → доменные ошибки → локализованные сообщения.
- Кэш: Room как источник правды для ленты и групп (single source of truth), сеть обновляет кэш; офлайн — чтение, правки только онлайн (YAGNI).
- Токены: `AuthInterceptor` добавляет access; `Authenticator` OkHttp на 401 выполняет refresh (с мьютексом против гонок); при провале refresh — выход на экран входа.
- Состояние UI и ввода переживает поворот/убийство процесса (`SavedStateHandle`).

## Безопасность клиента
- Только HTTPS; `network-security-config` без cleartext (исключение для debug-эмулятора), опциональный pinning.
- Токены в Keystore-защищённом хранилище; `allowBackup=false` или исключение секретов из бэкапа.
- Нет логирования чувствительных данных (HttpLoggingInterceptor только в debug и с маскированием `Authorization`).
- `FLAG_SECURE` не обязателен; поля пароля — `autofill`/password manager friendly.
- R8 + обфускация, подписание Play App Signing.
- Play Integrity API — токен в запросах регистрации (после согласования).
- CAPTCHA на регистрации — через WebView/SDK выбранного провайдера.

## Требования Google Play (закладываем заранее)
- Подписанный AAB, актуальный `targetSdk`, Data safety форма, политика конфиденциальности (URL).
- Удаление аккаунта внутри приложения + веб-страница для запроса удаления.
- UGC-политика: жалоба на контент, блокировка пользователя.
- Правильная работа с разрешениями (минимум; на старте их нет, кроме INTERNET).
- Доступность (TalkBack, размеры шрифта, контраст), тёмная тема, адаптивность (телефон/планшет).
- Локализация: строки в `strings.xml`, русский как основной, готовность к добавлению языков.
- Для iOS в будущем: KMP-общий слой (`core/model`, domain, часть data), UI на SwiftUI или Compose Multiplatform.

## Тестирование
- Unit: UseCase, ViewModel (Turbine), мапперы, валидаторы (username, теги, оценка).
- Интеграционные: репозитории с MockWebServer + in-memory Room.
- UI: Compose-тесты ключевых экранов (вход, создание рекомендации, фильтры).
- E2E (по возможности): сценарий против docker-compose бэкенда в CI.

## Согласованность с сервером и БД
- Клиент использует код, сгенерированный из `api/openapi.yaml`; правила валидации (длины, формат username, теги, оценка 1–10) берутся из контракта и дублируются в UI только для UX — сервер остаётся источником правды.
- Коды ошибок API — единый перечень, сопоставленный со строковыми ресурсами.

## Предложения и обоснования
- **Compose вместо View-системы:** современный стандарт, меньше кода, лучше тестируемость.
- **Мультимодульность с первого дня:** ускоряет сборку и обеспечивает границы; сложность умеренная благодаря convention plugins. Допустимо начать с `app` + `core` + `feature` без излишнего дробления.
- **Приглашения как App Links** (`https://podgon.app/invite/<token>`): удобно делиться, при отсутствии приложения — страница-заглушка со ссылкой на магазин. Нужна верификация домена (assetlinks.json).
- **Ввод кода подтверждения email** внутри приложения предпочтительнее ссылки из письма (меньше проблем с deep link и антифрод); ссылка — запасной вариант.
